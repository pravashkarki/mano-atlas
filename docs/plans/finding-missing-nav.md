# Plan: missing-nav

This work exists because 8+ pages ship with an empty `<div class="pagetools"></div>` container, leaving a reader on a phone with no way to jump between sections without long scrolling.

## Premise check

`build.py` line 772 renders `<div class="pagetools"></div>` for every non-index page. Lines 777 to 782 replace that empty div with an ordered onpage navigation list only when the page has 3 or more `<article class="card">` blocks. Confirmed empty `.pagetools` on approaches, child, casemgmt, nepal, pfa, gbv, hiv, ethics (audit ledger, `review/learning-ux-audit.md`). The CSS in `assets/style.css` line 577 hides empty pagetools via `:empty`, so the empty container renders as nothing on the page. The build-time replace logic already exists and works for pages with 3+ cards; the finding is that pages with 3+ cards are still getting empty divs, which means the card-count check or the card ID injection is failing for those pages. A content-based alternative would be to write the nav links manually in each `content/<slug>.html` file, but that is per-page editorial work and defeats the shared-finding principle.

## What ships

- A build-time fix so that every page with 3 or more section cards gets the onpage nav populated in `.pagetools` automatically.
- The fix targets the condition at `build.py:778` (`len(cards) >= 3`) and the card-id injection at lines 702 to 706; the root cause is that those pages are not producing the expected card count, so the nav never generates.
- For pages where the card count genuinely stays below 3, a content-based fallback: authors add the onpage nav markup directly into `content/<slug>.html` at the `<div class="pagetools">` slot.
- The phone acceptance test: a reader on a 390px viewport reaches any section of the page in one tap from the onpage nav, without scrolling past the first card.
- Both themes verified; the nav inherits existing `.pagetools` and `.onpage` CSS with no new rules needed.
- No per-page editorial work for pages that get the build-time fix; only pages below the 3-card threshold need manual nav links.

## Cases and decisions

- The build-time replace at line 782 already does the right thing; the fix is to ensure the preconditions hold (cards are injected, the regex matches). Open decision: whether to lower the threshold from 3 to 2 cards so more pages qualify automatically.
- Pages with exactly 2 cards (the threshold edge case): recommend lowering to 2, since even 2 sections benefit from onpage nav on phone. This is an open decision for the build author.
- Pages with 1 card (single-section pages): no nav needed; the empty pagetools stays hidden by CSS.
- The `secsub` paragraph at line 783-784 is used for the page description but does not affect the card count; it is not the cause of the empty nav.
- If a page has 3+ cards but still gets empty nav, the regex at line 777 failed to match; the fix is to correct the card markup in `content/`, not to change the regex, since the regex matches the existing card format.
- The `:empty` CSS rule at line 577 of `assets/style.css` correctly hides the empty div; no change needed there.

## Security

- The fix touches `build.py` only; no content files are modified by the build-time path.
- No new runtime, no new dependencies; the build stays stdlib Python.
- The onpage nav links are anchor links to existing section IDs; a broken link would be a build-gate failure (the card IDs are generated by the build, not hand-written).
- The nav markup is generated from existing card titles; no new strings are introduced, so no en/ne pair is needed.
- The change does not alter the visual layout beyond filling the existing pagetools slot; no new CSS classes.

## Validation

- Build the full site; every page with 3 or more cards has non-empty `.pagetools` containing an ordered list of anchor links.
- `grep -rn '<div class="pagetools"></div>' *.html` returns only pages with fewer than 3 cards (or the index page).
- Phone viewport test at 390px: every section link in `.pagetools` scrolls to the correct section; no link is broken or misaligned.
- `python3 build.py` runs clean; no new gate failures.
- Em-dash grep returns nothing; no new strings require en/ne pairs.
- The 8 confirmed pages (approaches, child, casemgmt, nepal, pfa, gbv, hiv, ethics) all have populated onpage nav in the built HTML.

## Rollout

Single commit on `dev` targeting `build.py`. The fix is a build-template change, not a per-page editorial change, so one commit covers all pages. Preview on Vercel, verify the 8 confirmed pages plus a spot check of pages with fewer than 3 cards, then founder go before merging to `main`. No separate rollout per page; the build fix propagates to every qualifying page at once.
